# Диагностика тайм-аута анализа

Дата: 14 октября 2026 г.

## Симптом и причина

После «Анализируем 50 отзывов…» интерфейс показывал общее «Операция превысила лимит времени. Попробуйте позже».

Реальная цепочка вызова: форма Streamlit → service.get_report → run_pipeline → llm.analyze_reviews → run_codex_json → run_child → codex exec. Перед запросом выполняется codex login status. Модель gpt-6.1-sol подключена через существующий вход ChatGPT. Заглушки используются только в unit-тестах; рабочая цепочка вызывает внешний CLI.

Причина сбоя: приложение ограничивало каждый ответ 120 секундами и завершало дерево своего CLI-процесса при превышении. Для реального отчёта этого недостаточно. Ранее были известны длительности 166–194 секунды, но бюджет приложения остался прежним. Проверка только тестов и сохранённых отчётов была недостаточна для заявления о готовности live-сценария.

В полноценной UI-репетиции обнаружен второй независимый сбой: после остановки worker Windows временно держала worker.stderr открытым. TemporaryDirectory при очистке выбрасывал PermissionError и заменял им результат сбора. Безопасный лог сохранил место сбоя: run_collection → TemporaryDirectory.__exit__ → shutil.rmtree. Файл оставался пустым; точный процесс, который держал его в момент очистки, не установлен. Поведение воспроизведено локальным Windows-тестом с реальным открытым дескриптором.

После устранения ошибки очистки открылся ещё один дефект коллектора: при общем лимите 60/65 секунд он сохранял snapshot только после обработки всей порции карточек. В диагностическом worker браузер запустился за 0,77 с, Яндекс вернул HTTP 200, DOM был готов за 11,16 с, а обработка карточек началась за 19,59 с и не завершилась до остановки родителем. Это не наблюдение бана: ограничение времени было израсходовано внутри чтения карточек. Отдельный локальный probe из настоящего Streamlit подтвердил правильный venv, передачу stdin и штатный код 2 на заведомо некорректный запрос без обращения к сайту.

## Контролируемое воспроизведение

- Минимальный реальный запрос production-адаптера: ok=true, 7,2 секунды.
- Вход: 50 самых новых отзывов из сохранённого реального сбора Кофемании (150 отзывов), prompt 15 140 символов.
- Для диагностического процесса временно разрешено 300 секунд на ответ; входные отзывы, prompt, схема, модель и reasoning low сохранены.
- Первый запрос: авторизация 0,14 с; реальный ответ модели 140,56 с. Старый бюджет 120 с завершил бы процесс раньше ответа.
- После проверки понадобилась предусмотренная единственная исправляющая попытка: авторизация 0,13 с; ответ 118,14 с.
- Итог: 50 отзывов, 10 тем, 258,99 с; все ID, цитаты и ссылки прошли production-валидатор. Сохранённые даты сбора не изменялись.
- CLI вернул события turn.completed и учёт токенов на обоих ответах. Это подтверждает обращение к модели, а не только запуск локального процесса.

Локальные доказательства: artifacts/debug-analysis-timings.json, artifacts/debug-coffee-50.json и artifacts/debug-coffee-50.md. Они игнорируются Git.

## Исправления

- Бюджет ответа модели увеличен до 300 секунд; лимит входа остаётся 50 отзывов.
- Тайм-аут проверки входа преобразуется в отдельную ошибку доступа, а не выдаётся за долгий анализ.
- UI сообщает, что не успела именно модель, указывает срок и возможность открыть предыдущий сохранённый отчёт.
- При исправлении отчёта и проверке цитат UI получает отдельные статусы.
- Готовый отчёт показывает имя модели и фактическую длительность анализа.
- Известные ошибки модели теперь сохраняют диагностическую запись: время, тип, имена файлов, номера строк и функций. Сообщения исключений, исходные строки кода, prompt, отзывы и авторизация в лог не пишутся.
- Тайм-аут не запускает автоматическую повторную отправку. Единственная исправляющая попытка разрешена только для ответа, который не прошёл проверку.
- Очистка временных файлов сборщика теперь выполняется в best-effort режиме стандартной библиотеки: занятый файл не уничтожает валидный результат и не подменяет исходную ошибку Яндекса. Два Windows-теста проверяют и успешный результат, и сохранение ошибки HTTP 429; обхода ограничения или повтора запроса нет.
- При чтении карточек проверяется общий deadline, время раскрытия ограничено оставшимся бюджетом, каждый готовый отзыв немедленно передаётся в snapshot. Пустая карточка пропускается без ожидания несуществующего текста. Подпись DOM читается одним атомарным вызовом вместо сотен отдельных обращений к странице.

## Автоматическая проверка

Новые регрессии сначала воспроизвели проблемы: ответ длительнее двух минут прерывался, тайм-аут входа имел неверный тип, UI скрывал этап, занятый stderr отменял результат сбора, а блокирующая кнопка или пустая карточка расходовала время чтения. После исправлений проходит полный набор 124 теста; compileall и pip check успешны. Дополнительно проверены передача статусов проверки/исправления в UI и отсутствие частных деталей в диагностическом логе.

## Проверка из настоящего интерфейса

Реальный live-refresh кнопкой Streamlit завершился успешно: 154 новых собранных отзыва → анализ 50 → 10 тем → проверка → сохранение → скачивание. Начало теста 18:36:06 МСК, новый сбор 18:37:09 МСК, модель 229,42 с, весь UI-сценарий 293,84 с. Даты нового bundle позже запуска теста, поэтому старый кэш не подменил свежую работу. Скачанные 17 988 байт Markdown совпали с render_markdown проверенного bundle. Доказательства: artifacts/ui-live-rehearsal.json, ui-live-coffee-report.md и ui-live-coffee-result.png.

## Границы

300 секунд — выбранный бюджет приложения, не обещание времени ответа провайдера. С исправляющей попыткой анализ может занять до 10 минут плюс сбор. Квота ChatGPT и доступность Яндекс Карт остаются внешними условиями.

Механизм codex exec, сохранённая авторизация и выход по JSON-схеме сверены с [официальной документацией OpenAI](https://learn.chatgpt.com/docs/non-interactive-mode).
