# Безопасная публикация

GitHub хранит исходный код. Docker упаковывает среду запуска; для загрузки кода он не требуется.
Способы запуска через Docker и на Windows описаны в README.
Сборку контейнера, браузер и интерфейс проверяет workflow `.github/workflows/verify.yml`; фактический результат смотрите в GitHub Actions.

## Что остаётся на компьютере

- Авторизация Codex: `auth.json` и каталог `.codex`.
- Переменные окружения `.env` и их локальные варианты. В Git разрешён только пустой шаблон `.env.example`.
- Профиль Chromium `.browser-profile`, включая cookies.
- Собранные отзывы, отчёты, снимки экрана и журналы в `artifacts`.
- Настоящие ключи, сертификаты и Streamlit `secrets.toml`.

Эти пути исключены через `.gitignore`. Отдельный `.dockerignore` разрешает передавать в сборку Docker только необходимые каталоги исходного кода, тесты и конфигурацию. Dockerfile дополнительно использует явный список `COPY`.
Не используйте `git add -f` для этих файлов и не загружайте всю папку проекта архивом.
Если задан нестандартный `ARTIFACTS_DIR`, держите его вне репозитория или добавьте его путь в `.gitignore` до запуска.

## Перед отправкой

1. Проверьте `git status --short` и `git diff --cached --stat`.
2. Проверьте содержимое подготовленных файлов через `git diff --cached` локально.
3. При первой загрузке проверьте историю: удаление секрета из текущего файла не удаляет его из старых коммитов.
4. Если секрет уже опубликован, сначала отзовите его, затем очистите историю.

Репозиторий: https://github.com/HEXYEBA/hse_domaha

Для доступа с этого компьютера выполните `gh auth login` и выберите вход через браузер.
Не вставляйте токены или содержимое `auth.json` в чат, README или исходный код.
При переносе проекта на другой компьютер Codex авторизуется отдельно; авторизация владельца вместе с кодом не передаётся.

## Авторизация Docker

Linux-зависимости Chromium, виртуальный экран Xvfb и Codex CLI устанавливаются при сборке. Вход выполняется отдельно пользователем через `docker compose run --rm --no-deps app codex login --device-auth`. Он сохраняется в локальном именованном томе, не в образе. Профиль браузера и отчёты имеют отдельные тома.
Авторизацию нельзя помещать в Dockerfile, `COPY`, аргументы сборки или слои образа. Не экспортируйте том `codex-auth` вместе с проектом. Каждый получатель репозитория использует собственный вход.
