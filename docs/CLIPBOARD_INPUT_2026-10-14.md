# Вставка ссылки: причина и исправление

## Что установлено

В настоящей пользовательской вкладке Chrome поле содержало посторонний старый текст, а в текущем буфере не было ссылки. Содержимое буфера в журнал не выводилось. После копирования фактического URL открытой карточки Яндекс Карт Ctrl+A → Ctrl+V заменил текст правильной ссылкой. Длина ссылки карточки ВкусВилла — 1163 символа, в действующий лимит она укладывается.

Дополнительно браузерная проверка воспроизвела **реальный баг формы**: после программной вставки поле визуально показывало новую ссылку, но отправка могла использовать прежний несохранённый черновик Streamlit form. Тест увидел правильное значение поля одновременно с ошибкой валидации старого текста. Одна смена оформления этого не исправляла.

## Изменено

- Перед полем добавлен локальный компонент с кнопками **«Вставить ссылку»** и **«Очистить»**. Clipboard API вызывается в браузере только после нажатия пользователя. Буфер сервера не читается.
- Вставка заменяет поле целиком. Ссылка повторно проверяется серверным нормализатором и приводится к короткому каноническому URL без поисковых параметров.
- Посторонний текст не подставляется; компонент сообщает, как скопировать адрес карточки. Содержимое неверного буфера не отправляется на сервер и не появляется в сообщении.
- При запрете доступа к буферу есть явное сообщение с обычным Ctrl+V, без молчаливого использования старого значения.
- После вставки, очистки или выбора примера создаётся новая версия виджета поля (`input_revision`). Старый несохранённый черновик больше не может подменить видимый адрес при отправке формы.
- Форма отправляет значение актуального поля. Повторно полученное событие компонента не применяется после ручного редактирования.
- Адрес-пример из placeholder удалён. Примеры организаций остаются отдельными кнопками и заполняют настоящий редактируемый URL.

## Проверено

**150 passed**, compileall успешен. Браузерная приёмка `artifacts/explicit-paste-verification.json`: `ok: true`.

Проверены настоящий Clipboard API, замена всего старого текста, отказ от неверного буфера без перезаписи корректного адреса, очистка, вставка другой ссылки, отправка новой ссылки с первой попытки, ручной Ctrl+V с последующей отправкой, отсутствие повтора старого события, скачивание правильного сохранённого отчёта и мобильная ширина 390 px. Содержимое скачанного отчёта сравнивалось побайтно с проверенным bundle. Новых запросов к Яндексу или модели для этих проверок не делалось.

Отдельно проверено **в реальной пользовательской вкладке Chrome** через расширение: кнопка вставки подставила фактический URL карточки; по новой ссылке открылся сохранённый отчёт Кофемании. После проверки возвращена ссылка пользователя на ВкусВилл `217633938954`, канонический URL виден в поле; анализ автоматически не запускался. Кнопки видны в `artifacts/explicit-paste-controls.png`.

Приложение не может определить, какую ссылку пользователь хотел скопировать, если в буфере находится другая корректная ссылка. Кнопка читает фактический текущий буфер, не использует историю вставок. Для копирования именно адреса карточки: на её странице Ctrl+L → Ctrl+C, затем «Вставить ссылку» в проекте.
