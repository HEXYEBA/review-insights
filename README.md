# Что говорят об организации

Локальное приложение для анализа публичных отзывов организаций на Яндекс Картах. Оно собирает доступные отзывы, группирует сильные стороны и проблемы, показывает подтверждающие цитаты и готовит Markdown-отчёт.

Учебный проект курса **LLM Agents**, версия **0.1.0**. Защита: **22 октября 2026 года**.

Проверено: 150 тестов на Windows; сборка Docker, 146 тестов Linux (4 проверки только для Windows пропущены), запуск Chromium и веб-интерфейса в [GitHub Actions](https://github.com/HEXYEBA/review-insights/actions/runs/38815238422). [Подробности версии и оставшиеся пункты сдачи](docs/RELEASE_0_1_0.md).

## Проблема и зачем нужна LLM

Владельцу организации трудно вручную сопоставить сотни отзывов. Сервис превращает доступную выборку в темы с цитатами, действия для руководителя и маркетинговые гипотезы. Это помогает выбрать, что проверить и улучшить.

Обычный код умеет считать слова, но «цена кусается» и «за эти деньги ожидал большего» выражают близкий смысл разными словами. **OpenAI, модель `gpt-6.1-sol` через Codex CLI** объединяет такие высказывания и предлагает гипотезы. Python собирает данные и проверяет структуру ответа, ID и дословность цитат. Это последовательный LLM-конвейер; автономный агент не требуется.

## Быстрый запуск через Docker

Нужен запущенный **Docker Desktop с Linux containers** (Windows/macOS) либо Docker Engine с Compose v2+ (Linux). Для анализа нужен собственный доступ к Codex через ChatGPT и доступная квота; авторизация владельца проекта не распространяется вместе с кодом.

Откройте PowerShell или терминал:

```sh
git clone https://github.com/HEXYEBA/review-insights.git
cd review-insights
docker compose build
```

Репозиторий может быть приватным: в таком случае сначала получите доступ у команды. Для точного воспроизведения опубликованной версии можно переключиться на её тег: `git checkout v0.1.0`.

Выполните **отдельный вход внутри контейнера**:

```sh
docker compose run --rm --no-deps app codex login --device-auth
```

Откройте адрес из терминала в браузере и введите показанный там одноразовый код. Код никому не пересылайте. Если этот способ входа запрещён, проверьте настройки безопасности своего ChatGPT или разрешения корпоративного пространства. Вход с device code описан в [официальной документации OpenAI](https://developers.openai.com/codex/auth/).

Проверьте модель и запустите интерфейс:

```sh
docker compose run --rm --no-deps app python -m scripts.check_llm
docker compose up -d
```

Откройте **[http://127.0.0.1:8503](http://127.0.0.1:8503)**. У проверки модели должны быть `ok: true` и имя модели. Она делает настоящий короткий запрос и использует квоту вашей подписки. В интерфейсе выберите пример → «Проанализировать» → дождитесь отчёта → «Скачать Markdown».

Для остановки и просмотра журнала:

```sh
docker compose logs --tail=50 app
docker compose down
```

Данные сохраняются в **локальных именованных томах Docker**: `codex-auth` — вход, `reports` — отчёты, `browser-profile` — отдельный профиль Chromium. `docker compose down` сохраняет их. Не добавляйте `--volumes`, если хотите сохранить вход и отчёты. Личный каталог `.codex` и личный браузер компьютера не подключаются. Интерфейс доступен только с этого компьютера.

В контейнере браузер работает через виртуальный экран Xvfb — окно Chromium на рабочем столе не появляется. CAPTCHA не обходится; при ограничении источника сбор может быть частичным.

### Настройки без секретов

По умолчанию `.env` не нужен. Чтобы изменить порт или модель, скопируйте `.env.example` в `.env` (`Copy-Item .env.example .env` в PowerShell) и отредактируйте его. Compose читает этот файл при запуске.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `MODEL_NAME` | `gpt-6.1-sol` | Модель, доступная вашему аккаунту |
| `APP_PORT` | `8503` | Порт интерфейса Docker на компьютере |
| `CODEX_BIN` | Автоматический поиск | Только локальный запуск: путь к Codex CLI |
| `ARTIFACTS_DIR` | `artifacts` | Только локальный запуск: каталог отчётов |

В Docker `CODEX_BIN`, `CODEX_HOME` и `ARTIFACTS_DIR` заданы внутренними путями в `compose.yaml`; менять их для обычного запуска не требуется. Локальный Python сам `.env` не читает: настройки передаются через переменные среды PowerShell. API-ключи проекту не нужны.

## Как это работает

1. Пользователь вставляет полную ссылку на карточку организации.
2. Python проверяет ссылку и запускает Playwright в отдельном процессе. Сборщик читает доступные тексты, даты и оценки из страницы браузера.
3. За один сбор сохраняется до 200 отзывов. Для анализа берутся до 50 самых новых по известным датам. Отчёт отдельно показывает, сколько отзывов собрано и сколько проанализировано.
4. Codex CLI передаёт выбранные отзывы модели `gpt-6.1-sol` через вход в ChatGPT. API-ключ не нужен. Reasoning effort задан `low`; запрос ограничен 300 секундами и может получить одну format/evidence-поправку.
5. Обычный код проверяет ссылки, ID, точные цитаты и то, что каждый выбранный отзыв либо поддерживает тему, либо явно исключён. Модель не получает право добавлять внешние факты.
6. Streamlit показывает отчёт и позволяет скачать его в Markdown. Успешный отчёт проверяется и сохраняется локально.

Отзывы — пользовательские тексты и могут содержать неверные или устаревшие сведения. Отчёт отражает только собранную выборку, а не мнение всех клиентов и не внутренние показатели организации.

## Установка и запуск в PowerShell

Из корня клонированного репозитория (локальная рабочая папка автора называется `review-insights`):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:PLAYWRIGHT_BROWSERS_PATH = "0"
.\.venv\Scripts\python.exe -m playwright install chromium
Remove-Item Env:PLAYWRIGHT_BROWSERS_PATH
```

Проверьте вход Codex и запустите тесты:

```powershell
codex login
.\.venv\Scripts\python.exe -m scripts.check_llm
.\.venv\Scripts\python.exe -m pytest -q
```

Запустите приложение:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address=127.0.0.1 --server.port=8502 --server.headless=true --browser.gatherUsageStats=false
```

Откройте [http://127.0.0.1:8502](http://127.0.0.1:8502), выберите пример или вставьте ссылку. Установка Chromium и приложение используют локальный каталог проекта; личный профиль браузера не читается.

## Обычный показ и сохранённый отчёт

- **Проанализировать** открывает проверенный отчёт моложе 6 часов, если он есть. Иначе приложение собирает отзывы, запускает анализ и сохраняет результат.
- **Обновить с Яндекса** явно запускает новый сбор и анализ. Если обновление не удалось, предыдущий файл остаётся доступен отдельно.
- **Открыть сохранённый отчёт** читает только локальный файл. Этот режим подходит для защиты без повторного обращения к Яндексу или модели; он показывает фактическую дату сбора, даже если отчёт старше 6 часов.

Проверенные отчёты находятся в `artifacts/reports/<id организации>.json`. Они содержат тексты отзывов и исключены из Git. Не отправляйте их без необходимости. Для live-сбора Playwright использует отдельный профиль проекта `.browser-profile/yandex`; он не копирует личный профиль. Окно отдельного Chromium может быть видно во время сбора. При ограничении Яндекса приложение останавливается и сохраняет уже собранную часть.

## Ограничения MVP

- За один сбор — не более 200 доступных отзывов; за один запрос модели — не более 50.
- Если сортировку по новизне подтвердить нельзя, отчёт предупреждает об этом. Выбор анализа всё равно сортирует отзывы с датами; неизвестные даты остаются в конце.
- Яндекс может временно не показать карточки, изменить разметку или запросить проверку посетителя. При HTTP 429 сборщик сообщает об ограничении, сохраняет уже собранные отзывы и предлагает повторить позже; автоматических повторов и обхода защиты нет.
- Число текстовых отзывов и число оценок на карточке — разные показатели.
- Старые отзывы могут описывать уже изменившуюся ситуацию. Даты и период всегда показаны.
- Модель получает до 300 секунд на ответ. При необходимости разрешена одна исправляющая попытка: весь анализ может занять до 10 минут плюс время сбора. В реальной диагностике 50 отзывов Кофемании проанализированы за 259 секунд с одним исправлением; прежний лимит 120 секунд обрывал ещё работающую модель. Интерфейс показывает этап исправления, имя модели и фактическое время готового анализа.
- Данные в `artifacts/` остаются локальными и игнорируются Git. JSON-отчёт содержит выбранные тексты отзывов; делитесь им осознанно.

## Проверка и статус

Проверка внутри Docker без входа и без обращения к модели:

```sh
docker compose run --rm --no-deps app python -m pytest -q
```

[GitHub Actions](https://github.com/HEXYEBA/review-insights/actions) собирает образ без авторизации владельца, запускает тесты, проверяет Chromium на локальной HTML-странице и доступность веб-интерфейса. Эти проверки не подтверждают доступность Яндекса и модели для другого аккаунта: их проверяет отдельный реальный запуск.
